# kwantil-research

Analysis code and derived results for the studies published at
[kwantil.com](https://kwantil.com). Every figure and every number in those
articles is produced by code in this repository, from public data, with fixed
seeds.

The point of publishing this is narrow and specific: **a validation finding you
cannot reproduce is an assertion.** These analyses argue that stated
uncertainty is often not what it claims to be, and that argument is worth
nothing if the reader has to take it on trust.

| Analysis | Article | Data source |
|---|---|---|

| [`var-backtest-tail-risk`](analyses/var-backtest-tail-risk/) | [Tail Risk Backtesting: When the Test Improves and the Model Does Not](https://kwantil.com/papers/did-the-model-get-better/) | Yahoo Finance via `yfinance` |
| [`tool-wear-calibration`](analyses/tool-wear-calibration/) | [Tool Change Intervals, Audited Against Measured Wear](https://kwantil.com/papers/tool-wear-calibration-audit/) | NASA Milling Data Set |

The live scoreboard for the tail-risk study, with its full methodology manual,
is at [var-backtest.mtanti.com](https://var-backtest.mtanti.com).

Each analysis directory carries four things:

| File | What it is |
|---|---|
| `README.md` | what the analysis found, in a page |
| `DATA.md` | how to fetch or rebuild every input and output |
| `notebooks/` | the experiment, run step by step, with the statistics computed inline |
| `report/*.pdf` | the published article as a print report |

**The notebooks are the experiment, not a tour of it.** They call the library for
the parts that are genuinely heavy (fetching prices, walking a backtest forward,
fitting GARCH) and compute the statistics in the notebook, because the arguments
here are about how a test is constructed and you cannot see that if the answer
arrives from inside a function you did not open. Each ends with what the result
does **not** support.

**The PDF is generated by printing the live article** rather than being authored
separately. A separately written report drifts from the article the moment either
is edited, and then the authoritative version is whichever one the reader
happened to open. Paper gets its own design rather than the screen design with a
white background: see `apps/site/src/print.css` in the site repository.

## What is deliberately not here

**Bulk data files.** `*.parquet` and friends are gitignored, derived outputs
included. An earlier revision shipped four small derived parquets on the
grounds that they were cheap; that made the repository a partial mirror of its
sources for no reproducibility gain, since anyone rebuilding gets them in
seconds. What ships is limited to a few kilobytes of aggregate results and
figure data — each analysis `DATA.md` names exactly which files those are, and
how to rebuild everything else.

**Raw third-party data.** Nothing in this repository mirrors a data provider.

- Yahoo Finance terms do not permit redistributing their price data. The price
  cache is not published; `fetch_prices` rebuilds it.
- The ENTSO-E pulls are large and better re-fetched than mirrored. Bring your
  own API token, set `ENTSOE_API_TOKEN`, and run the pull scripts.
- The NASA Milling Data Set is a 98 MB set of MATLAB files distributed by the
  NASA Prognostics Center of Excellence. Fetch it from the source.

**Row-level derived series.** Some outputs are one row per instrument per day
and sit close enough to redistribution to be worth avoiding. Aggregate results
ship; row-level series are rebuilt.

Every analysis ships the script that fetches its own inputs, so the exclusion
costs a download rather than reproducibility.

## Reproducing

See [REPRODUCING.md](REPRODUCING.md) for environment setup and the exact
commands per analysis.

The shortest path to the central claim of the tail-risk article:

```bash
cd analyses/var-backtest-tail-risk
python scripts/run_backtest.py --method all                    # ~6 min
python scripts/as_null_sensitivity.py \
    --details experiments/factorial/t/details.csv
```

That reproduces the six-null sweep: the same five models, the same statistics,
and a verdict that moves from zero passes to ten depending on which reference
distribution you assume.

## How this repository is maintained

The working copies live outside this repository. `scripts/sync.py` vendors code
and derived results in from them using an **explicit allowlist**, so a file is
published only if a rule names it.

That is a deliberate choice rather than a convenience. The source trees sit next
to directories holding client material and commercial planning, and an
exclude-list publishes whatever somebody forgot to exclude. Three guards run on
every file: the allowlist, a size ceiling that catches raw data pulls even if a
glob is written too loosely, and a credential scan. A tripped guard fails the
sync rather than warning.

```bash
python scripts/sync.py --check   # report what would change, write nothing
python scripts/sync.py           # perform the copy
```

## Corrections

Findings here have been revised, including in ways that did not flatter the
original result. Those revisions are recorded in the analyses and in the
articles rather than quietly applied.

The clearest example is in the tail-risk study, where an expected-shortfall
diagnostic improved after three simultaneous changes and the development log
credited the wrong one. The factorial that corrected it is in
`analyses/var-backtest-tail-risk/experiments/`, and its result is the subject of
the article rather than a footnote to it.

If you find an error, please open an issue. A methodology that only records the
decisions that flatter it is not a record.
